# USMCA Share Modes

**Audience:** engineers debugging USMCA rates for Canada/Mexico; data managers maintaining product-share files.

USMCA-eligible products imported from Canada or Mexico receive a duty reduction proportional to a "USMCA share" — the fraction of imports that historically claimed USMCA preferences. The pipeline supports five modes for sourcing this share, plus a binary fallback when no shares file is available. This doc enumerates them; for the rationale on which to choose, see [`analysis/usmca_share_method_comparison.md`](analysis/usmca_share_method_comparison.md).

## The five modes

Implemented in `load_usmca_product_shares()` at `src/helpers.R:2054-2233`. The active mode is set at `config/policy_params.yaml:467-482`.

| Mode | What it does | Source file pattern |
|---|---|---|
| **`h2_average`** *(recommended baseline)* | Trade-weighted average of months 7-12 of the configured year | `resources/usmca_product_shares_{year}_{07..12}.csv` averaged |
| **`annual`** | Single annual file | `resources/usmca_product_shares_{year}.csv` |
| **`monthly`** | Per-month file based on revision effective_date | `resources/usmca_product_shares_{year}_{MM}.csv` (with fallback to earlier month if missing) |
| **`fixed_month`** | Configured single month | `resources/usmca_product_shares_{year}_{fixed_month}.csv` |
| **`hybrid_rolling`** | Q1 average for Jan-Mar; 3-month trailing average for Apr-Dec | Combination of monthly files |

The `analysis/usmca_share_method_comparison.md` memo (2026-03-29) recommends `h2_average` as the steady-state baseline because post-tariff months 7-12 of 2025 reflect the new USMCA claiming behavior without the H1 transient.

## Binary eligibility fallback

When `load_usmca_product_shares()` cannot find any shares file (or the configured file is empty), the pipeline falls back to **binary** USMCA eligibility:

- For each product, read the HTS `special` field
- If `special` contains an `S` or `S+` indicator code, the product is USMCA-eligible
- Eligible products from Canada/Mexico get a full 100% reduction on applicable rates (`rate × 0` instead of `rate × (1 − usmca_share)`)
- Non-eligible products from Canada/Mexico are treated like any other origin

This is a *fallback*, not a selectable mode — you don't set `mode: 'binary'` in the config. It activates automatically when the configured mode's input files are missing.

## What is NOT a mode

`todos.md` previously referred to USMCA modes as "binary vs product_shares vs hs8_blended." That framing was wrong:

- **`binary`** is the fallback described above, not a configurable mode
- **`product_shares`** isn't a mode name — it's the general concept that the five real modes implement
- **`hs8_blended`** doesn't exist anywhere in the codebase. It may have been a planned or remembered alternative; if you implement one, it's a new mode requiring a `helpers.R` extension

## Decision tree

To check or change the active mode:

1. Read `config/policy_params.yaml`, look for the `usmca_shares:` block (around line 467-482):
   ```yaml
   usmca_shares:
     mode: 'h2_average'   # 'h2_average', 'annual', 'monthly', 'fixed_month', 'hybrid_rolling'
     year: 2025
   ```
2. Confirm the source files exist for that mode (see "source file pattern" column above).
3. If you change the mode, re-run the pipeline; affected revisions will pick up new USMCA shares on the next build.

## Application in the rate engine

`src/06_calculate_rates.R:2080-2135` (step 7) applies the share to Canada/Mexico-origin rows:

```r
rate_reduced = rate × (1 − usmca_share)
```

For chapter-87 auto products specifically, the share is further scaled by `us_auto_content_share` (0.40) from `config/policy_params.yaml:427-445`. See [`auto-rebate-logic.md`](auto-rebate-logic.md) for the auto-stack ordering.

## Maintaining shares files

The `resources/usmca_product_shares_{year}_{MM}.csv` files are generated by `download_usmca_dataweb.R` (USITC DataWeb pull). To refresh:

```bash
Rscript src/download_usmca_dataweb.R --monthly --year 2025
```

Schema is `hts10`, `cty_code`, `usmca_share` plus optional `total_value` and `usmca_value` for diagnostics.
