# Tariff Rate Tracker — Frontend

Interactive duty rate calculator and tariff visualization tool. Queries the full HTS tariff dataset (19,956 products, 240 countries, ~613M rows across 132 revisions) via a DuckDB-backed API server that reads partitioned Parquet files.

## Architecture

```
Browser (React + Vite)          API Server (Express + DuckDB)
  :5173                            :3001
  +-----------------------+        +---------------------------+
  | React SPA             |  /api  | DuckDB (in-memory catalog)|
  | - Dashboard (JSON)    | -----> | - Parquet dataset (8.2 GB)|
  | - Rate Lookup (JSON)  |  proxy | - Arrow IPC streaming     |
  | - Multi-Country (IPC) |        | - JSON endpoints          |
  +-----------------------+        +---------------------------+
```

- **Rate Lookup**: Single product + country query via `/api/rates` (JSON). Returns all revision periods.
- **Multi-Country Comparison**: Queries multiple countries simultaneously via `/api/rates/arrow` (Arrow IPC). Zero-copy deserialization on the frontend using `apache-arrow`.
- **Dashboard**: Reads pre-computed aggregate JSON files from `public/data/`.

## Prerequisites

- **Node.js** >= 18
- **npm** >= 9
- **Parquet dataset** at `../data/timeseries/rate_timeseries_parquet/` (generated by the R pipeline via `Rscript scripts/combine_snapshots.R`)

## Setup

```bash
cd frontend

# Install dependencies
npm install
```

## Running

You need **two processes**: the API server and the Vite dev server.

### Option 1: Separate terminals (recommended)

Terminal 1 — API server:
```bash
node server.js
```

Terminal 2 — Vite dev server:
```bash
npm run dev
```

### Option 2: Single command

```bash
npm run dev:all
```

This runs `node server.js & vite` in one shell. The API server runs in the background.

### Accessing the app

Open **http://localhost:5173** in your browser. The Vite dev server proxies all `/api/*` requests to the API server on port 3001.

## API Endpoints

| Endpoint | Method | Description |
|----------|--------|-------------|
| `/api/rates?hts10=...&country=...` | GET | Rate lookup (JSON). Supports `revision`, `date` filters. |
| `/api/rates/arrow?hts10=...&country=...` | GET | Rate lookup (Arrow IPC stream). `country` accepts comma-separated codes for multi-country queries. |
| `/api/products?q=...` | GET | HTS code autocomplete (prefix search, returns up to 50 matches). |
| `/api/health` | GET | Health check with row count. |

### Example queries

```bash
# Single product + country (JSON)
curl "http://localhost:3001/api/rates?hts10=8471500150&country=2470"

# Multi-country comparison (Arrow IPC)
curl -o rates.arrow "http://localhost:3001/api/rates/arrow?hts10=8471500150&country=5700,1220,2010,4280"

# HTS code search
curl "http://localhost:3001/api/products?q=8471"

# Health check
curl "http://localhost:3001/api/health"
```

## Data Pipeline

The frontend depends on data generated by the R pipeline. To regenerate:

```bash
# From the project root (not frontend/)

# 1. Build snapshots into partitioned Parquet dataset
Rscript scripts/combine_snapshots.R

# 2. Generate daily aggregate CSVs
Rscript scripts/run_daily_from_parquet.R

# 3. Generate frontend JSON files (countries, timelines, daily aggregates)
Rscript scripts/prepare_frontend_data.R
```

The API server reads the Parquet dataset directly — no JSON export needed for rate lookups.

## Static Data Files

Pre-computed JSON files in `public/data/` (loaded at app startup for the dashboard):

| File | Size | Contents |
|------|------|----------|
| `countries.json` | 28 KB | Census codes + ISO alpha-2/3 + partner groups |
| `revision_timeline.json` | 19 KB | 132 HTS revisions with policy events |
| `daily_overall.json` | ~1.0 MB | Daily aggregate tariff statistics |
| `daily_by_authority.json` | 773 KB | Daily rates by tariff authority |
| `daily_by_country_summary.json` | 8.5 MB | Per-country per-revision summaries |
| `sample_rates.json` | ~505 MB | Sample product rates (used for quick-select buttons) |
| `program_symbols.json` | 171 KB | Special-program symbol map + Column 2 list (de-hardcoded, per revision) |
| `program_countries.json` | 162 KB | Country → preference-program membership (GSP/AGOA/CBERA + FTA) |
| `program_requirements.json` | 8 KB | Per-program eligibility requirements ("missing facts") |
| `legal_refs.json` | 108 KB | Audited proclamations / EOs / CBP messages per Ch99 authority |
| `duty_citations.json` | 24 KB | `reason_code` → citation / narrative registry |

The last five are the de-hardcoded program and legal-reference bundles, generated from the HTS General Notes and Chapter 99 PDFs during the R build (not by `prepare_frontend_data.R`). See [../docs/PROVENANCE_PIPELINE.md](../docs/PROVENANCE_PIPELINE.md).

## Build for Production

```bash
npm run build
```

Output goes to `dist/`. For production deployment, the API server (`server.js`) must run alongside the static file server. Set `API_PORT` environment variable to override the default port 3001.

## Environment Variables

| Variable | Default | Description |
|----------|---------|-------------|
| `API_PORT` | `3001` | Port for the DuckDB API server |

## Tech Stack

- **Frontend**: React 18, TypeScript, Vite, Tailwind CSS, Recharts, Radix UI
- **API Server**: Express, DuckDB (`@duckdb/node-api`), Apache Arrow
- **Data Transfer**: JSON (small queries), Arrow IPC (large result sets)
- **Data Storage**: Partitioned Apache Parquet (ZSTD compressed)
